六阶段路线

建议按顺序推进。前两阶段不写代码，第三阶段开始边读边在浏览器验证。

第 0 阶段
20 分钟

建立权限地图

目标是听懂这个系统在解决什么问题：普通 RBAC 只管页面入口，这里还要管区域、组织、摄像头和二次授权。

  • 读 docs/权限设计说明.md 的第 1-5 节。
  • 读 docs/海康对照.md 的“一句话结论”和“逐项对照表”。
  • 产出一句自己的理解：访问 = 功能关 + 数据关，超管例外。

读懂只读鉴权引擎

这是最核心、也最值得先读懂的代码。它只判断能不能访问，不负责保存权限。

第 4 阶段
90 分钟

攻克受控委派

这是最容易绕的部分：创建或编辑角色时，操作者只能授出自己当前可授的范围，但保存时要保留他看不见的旧权限。

  • 读 internal/service/delegation.go 的 GrantableSet 和 MergeDelegated。
  • 读 internal/service/role.go 的 GuardManageRole。
  • 背下合并公式：(提交 ∩ 可授范围) ∪ (原有 \ 可授范围)。
  • 区分可见角色 ManageableRoles 和可编辑删除角色 OwnedRoles。

第 5 阶段
60 分钟

理解列表、分页和写操作

鉴权是“已知目标能不能访问”，分页是“未知列表哪些可见”。这两类问题不能用同一种实现方式。

  • 读 internal/service/paging.go，看 scope 如何变成 SQL WHERE。
  • 读 internal/service/area.go、org.go、resource.go，看写操作如何同时过功能关和数据关。
  • 读 resource/public/index.html，理解前端如何按可授范围隐藏或置灰节点。
SQL 下推 懒加载树 搜索 500 截断 写时鉴权

四个必做练习

做完这些，基本能从业务现象倒推到代码实现。

练习 1：一条资源鉴权链路 用李四验证 102 球机 live/playback 的差异，再回到 CheckResource 对 trace。
练习 2：一条树权限链路 用张三验证事件图片测试可管理、园区A不可管理，再回到 checkTreeScope 看 path 前缀。
练习 3：一次角色保存链路 从前端保存角色开始，追到 perm.go、MergeDelegated、SaveRole、Reload。
练习 4：一次分页过滤链路 看 /api/app/area-children 如何把用户范围变成 SQL 条件，而不是全量取回再过滤。

学习完成标准

不用背代码，能稳定回答这些问题就算入门。

  • 能解释“应用端有权不等于后台管理有权”。
  • 能解释为什么授权父节点子树后，未来新增子节点自动继承。
  • 能解释资源权限里“区域继承”和“单资源精细覆盖”的优先级。
  • 能解释为什么编辑角色时要保留操作者看不见的旧权限。
  • 能区分角色“可见”和“可编辑/删除”的不同来源。
  • 能说明为什么列表分页必须把权限下推到 SQL。
